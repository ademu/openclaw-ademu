## 0. Context

Today an OpenClaw agent cannot reach Ademú. This slice ships the connector: a public npm-shaped plugin
(`@ademu/openclaw-ademu`, manifest id `ademu`) that bundles the adc daemon via `@ademu/adc-bin`, enrolls an
agent device through the four-word ceremony (wizard door + owner-gated chat-tool door), and then runs the
device as a resident OpenClaw channel: the daemon's durable, replayable stream drives ingress and the
read-receipt-weight ack fires at adoption (before the model runs), owner-only DMs, mention manners in rooms, typing while composing, E2EE replies. Zero changes to the
daemon/protocol/packages; zero publishing (npm/ClawHub are launch-calendar items).

## ✅ STOP CONDITION RESOLVED — owner chose **Option B** (2026-09-04): the daemon is the durable store

**Decision (owner, for the design entry):** the ADC already provides a durable, replayable, cursor-addressed stream with dedup by `message_id` — the ingress monitor was double-buffering; the trust gate makes the simpler design the honest one. Decision 1's promise holds ("blue tick = the daemon retained the message until OpenClaw committed its adoption — durably watermarked and cumulatively acked — before the model runs"); its letter changes from after-admit to **after-adoption**. Riders: **R1** serialize ADOPTION per account (await `onAdopted` of N before dispatching N+1); model runs proceed concurrently after adoption — cumulative acks demand adoption order, not run order. **R2** dedupe via a persisted watermark `{ deviceId, adoptedSeq }` per account (not a ring): a replayed `seq ≤ adoptedSeq` for the same deviceId → ack without dispatch; new deviceId → reset. **R3** the cumulative-ack halt rule is unchanged: pre-adoption failure → no ack, halt consumption, `recovering`, throw → restart replays; gated messages ack immediately after the gate decision. **R4** declare the receive ack policy truthfully — verified: `after_agent_dispatch` = "After the agent run is dispatched" (`docs/plugins/sdk-channel-inbound.md:124`) and core's `onAdopted` IS the run-start marker (`agent-runner-execute.ts:270-273`), so that is the declared value and the only one proven. **Recorded (Tier C note, raise with maintainers):** external plugins are gated from durable ingress by policy (`registry-runtime.ts:169-186`); B is valid in both tiers. §2 R2b and T7 rewritten below; the six parked findings folded (Codex R2 #1 moot, #2/#3/#4/#6/#8 folded).

## 2. Design refinements to the spec text (flagged for the owner; defaults chosen)

- **R1 — Daemon identity is a channel-level setting, inherited by accounts, and DEFAULT-ISOLATED (approval rider R2, 2026-09-03).** `socketPath?`/`dataDir?` live on `channels.ademu` (root-level fields are the inheritance base; an account may override). **Default `dataDir` = `<OPENCLAW_STATE_DIR>/ademu/adc`** (via `resolveStateDir` from `state-paths`), **default `socketPath` = `<dataDir>/adc.sock`**. The plugin passes ALL THREE `ADC_DATA_DIR`, `ADC_SOCKET_PATH` AND **`ADC_SESSION_SOCKET_PATH=<dataDir>/adc-session.sock`** to `ensureDaemon`'s `env` (resolution) AND through its own `spawnFn` (child env — V28 correction; Codex R6 #4: the SESSION socket resolves independently — `$ADC_SESSION_SOCKET_PATH` > config > `$XDG_RUNTIME_DIR/adc-session.sock` (non-macOS) > `<data_dir>/adc-session.sock`, `PROTOCOL.md:107-125`, `config.rs:432-450` — so without the third variable a Linux XDG rung would collide across daemons; the daemon itself refuses session==control). The ownership row stores all three resolved paths and validates them against `daemonInfo().socket_path`/`session_socket_path`. **Daemon identity = the validated pair `(dataDir, controlSocket)`** (Codex R1 #18, R3 still-open #18): both paths are canonicalized for the identity check with `fs.realpathSync` of the deepest existing ancestor + the remaining verbatim tail (Ademú itself joins verbatim and never normalizes, `resolve-control-socket-path.js:22-26`, so `..`, relative, and symlink aliases must collapse on OUR side); an explicit `socketPath` override must be unique per data dir — two accounts naming different sockets for one data dir, or one socket for two data dirs (after canonicalization), are a config validation error (`inspectAccount` reports it; `startAccount` blocks). Reference counting is keyed by that identity. **The control socket is for control only; the SESSION socket is always `daemonInfo().session_socket_path`** obtained on every account start (Codex R1 #6; ts-control README:61-73) — never the configured path, never stored in config. An operator's own adc (e.g. `~/.local/share/adc`) is reached only by explicit config.
- **R2 — Daemon ownership is DURABLE, two modes (approval rider R2).** The **ownership record** is a row in the plugin's SQLite DB (`daemon_ownership`, keyed by canonical `dataDir`; R9 — replaces the in-dir JSON marker; losing the DB degrades OUR daemon to foreign = attach-only, the safe direction). Hardened per Codex R1 #4 (the earlier in-dir `wx` JSON marker text is RETIRED everywhere — Codex R4 #11; the row is the marker): (a) **claim BEFORE spawn, atomically** — on a FRESH dir (absent or empty) create the dir 0700 and INSERT the claim row (`state:"claimed"`; a unique-key conflict → re-read and re-decide); (b) after the spawn's hello, **bind** the row to the instance: `{ pluginId:"ademu", dataDir, controlSocket, sessionSocket, pid, pidStartedAt (from `ps -o lstart=`), daemonStartedAtMs (daemonInfo.started_at_ms), daemonDataDir (daemonInfo.data_dir), adcVersion (parsed leading semver), bundledAdcBin, claimedAtMs }`; (c) `fresh` but `ensureDaemon` reports `spawned:false` (a listener won the probe-then-spawn race) → treat as **foreign** (exact-state, exact-generation CAS delete of our `starting` row). At `acquire()`: **bound marker present** → plugin-owned: spawn / stop / respawn / upgrade allowed, including after a gateway restart finds our detached daemon alive — the kill target is authorized only if `daemonInfo()`'s `data_dir`, `socket_path` AND `session_socket_path` equal the bound row, `started_at_ms` matches, the pid is alive, its `ps` command is `adc daemon run` and its `pidStartedAt` matches (defeats pid reuse); otherwise we log, do not kill, and treat as foreign. **No marker → foreign**: attach-only — never spawn, never kill, never upgrade; on loss → `recovering` while the client's reconnect loop probes; never the restart-throw. **Displacement** (`AlreadyAttachedError` after the client's bounded grace — reconnects never re-apply takeover, `client.js:498`): terminal `blocked` ("another process attached to this device") in BOTH modes, no kill/restart (Codex R1 #2). **Upgrade** decision compares the marker's/daemonInfo's parsed leading semver against the exact `@ademu/adc-bin` version (`daemonInfo.version` is build-suffixed, e.g. `0.2.0 (source)` — Codex R1 #5); unparsable → no upgrade, log. (Codex R1's "prefer a control `shutdown` op" was RIGHT and my decline was wrong — the daemon exposes `shutdown` (`PROTOCOL.md:647`); adopted in T5 via the client's generic `request()`, kill as fallback.) Daemon death for an OWNED daemon: observe the child exit, or the 5th consecutive `retry` when re-attached to our own detached daemon → `recovering` → `client.close()` → the session's `lifetime` promise REJECTS → `startAccount` rejects → gateway supervisor restarts the account → `ensureDaemon` respawns (Signal's mechanism). This removes V29 as production behavior and makes E2E isolation the default; E2E leg 8 tests the foreign path.
- **R2b — Ack at adoption; the daemon is the durable store (Option B, owner 2026-09-04; supersedes the ingress-monitor design).** No harness queue. The plugin owns ONE sequential event loop per account over `client.events()`. For each `message_received` (after shape validation — `seq` a safe integer ≥ 0, `message_id`/`group_id`/`sender_user_id` non-empty strings; malformed → **gate decision: ack immediately**, log class only): (1) **watermark** `{ deviceId, adoptedSeq }` persisted in the plugin's own SQLite DB (**R9**, Codex R3 #6: `<stateDir>/ademu/ademu.sqlite` via Node's built-in `node:sqlite` (`DatabaseSync`, verified on 24.15.0; unflagged since Node 22.13), `journal_mode=WAL`, `synchronous=FULL`, tables `watermarks(account_id PK, device_id, adopted_seq)` and `daemon_ownership(...)` — replaces the JSON files: OpenClaw's storage rule (`AGENTS.md:115-116`) forbids JSON sidecars for cursors/checkpoints/plugin scratch and the Tier-C goal means we follow it; tmp+rename is atomic but not power-loss durable) — `hello.device_id !== deviceId` → NOT a silent reset: identity binding (R3 #10) fails closed first (below); the watermark row is keyed by accountId and stores the bound deviceId; `seq ≤ adoptedSeq` → replay of an already-adopted message → **ack without dispatch**; (2) self-sent → ack; (3) DM stranger / room mention gate → **ack immediately after the gate decision** (rider R3);
